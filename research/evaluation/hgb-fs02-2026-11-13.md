# hgb-fs02-2026-11-13: the gateway's first trained model

Built on 13 Nov 2026 for MVP sprint 7 by `research/training/train_gateway_model.py`. This is
the **integration model**: it shows the gateway running a real HistGradientBoosting artefact on
the features it can compute itself (schema fs-0.2). It is not the fraud experiment's result.
The experiment (team folder `02-research/fraud-experiment`, owner Noppawut) answers the
research question with richer IEEE-CIS inputs and keeps its final holdout sealed; this model
never read that holdout either.

| Item | Value |
| --- | --- |
| Data | IEEE-CIS `train_transaction.csv`, days 0 to 146 only (487,837 rows). Days 147+ are the experiment's sealed holdout and were cut out before the data left the team folder. |
| Splits | fit days 0-110 (383,118 rows, 3.42% fraud); tune days 111-128 (56,900); report days 129-146 (47,819), unseen by fitting and threshold choice |
| Model | `HistGradientBoostingClassifier(max_iter=300, max_leaf_nodes=31, min_samples_leaf=50, learning_rate=0.1, l2_regularization=10)`, chosen over the experiment's baseline setting by average precision on the tune days (0.1134 vs 0.1108) |
| Features (9) | `amount_cents`, `card_attempts_10m`, `card_attempts_1h`, `card_attempts_24h`, `card_attempts_7d`, `card_attempts_30d`, `card_seconds_since_last`, `card_mean_amount_30d`, `amount_to_card_mean_30d` |
| Card key | card1 to card6 + addr1 joined, as a stand-in for the vault's card fingerprint (empty when card1 or addr1 is missing) |
| Not used | `email_*` and `ip_*` (IEEE-CIS has no email address or IP), `card_blocked_24h`, `card_allowed_30d` (no screening outcomes in the data), `card_distinct_emails_24h` |
| scikit-learn | 1.7.2 (same as the gateway) |
| SHA-256 of model.joblib | `a7dee1a5216750205b2c731ac7d5874a3ec0f5e1f72c17b57ebddd770e41ec5e` |

The policy ships in the manifest as `policy-hgb-fs02-2026-11-13` and replaces `policy-0.1`.

## How to read this

* The model is weak. The experiment's current-transaction HGB reached ROC-AUC 0.81 on its
  tuning period with inputs the gateway does not collect (product code, card network and type,
  email domain, address). Collecting those is a feature-schema change for a later sprint.
* IEEE-CIS amounts are USD; the gateway reads them as SGD cents. Card attempts in IEEE-CIS are
  processed transactions, while the gateway counts every screening attempt, including blocked
  ones. Both are known mismatches, so live scores are indicative only.
* Development numbers, single run, no uncertainty interval. Not a claim about real fraud rates.

## Latency (NFR-PER-02)

`manage.py loadtest_screening --rate 20 --seconds 60` on the Docker stack (gunicorn gateway,
Postgres 17, 4 vCPU cloud VM, 5,000 earlier screening events): 1,200 screenings at 20.0/s,
screening as checkout calls it p50 16.9 ms, **p95 21.6 ms**, p99 25.8 ms, max 118.5 ms; none over
the 500 ms budget. PASS against p95 <= 200 ms. With the stub model the same run gives p95 about
20 ms, so the model adds about 2 ms. Before `OMP_NUM_THREADS=1` (now set in
`gateway/config/settings.py`) the model's OpenMP threads oversubscribed the CPUs and p95 was
66 ms.
